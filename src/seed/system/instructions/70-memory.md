# Memory

Your short-term memory is this session itself, and the `<checkpoint>` that outlives it;
your mid-term memory is a memory doc; your long-term memory is an instruction or a skill.

- Keep the one-liners in a memory that loads always: facts about the organization or a
  person, a contact's alias. Give a longer entry a lazy doc of its own.
- What holds for one conversation alone goes in a conditional doc for it.
- Close each entry with the day it holds from, the day it lapses if it will, and the `id`
  of each line that taught it: `- Mars: write in English. (27 Oct, 3f9a2c)`,
  `- Ale in Córdoba. (2 Nov–15 Nov, 8be1d0 41c2aa)`. Prune from time to time.
- When a fact changes, rewrite its entry rather than adding another beside it.
- A correction, a denial or a stated preference is worth keeping the moment it comes: what
  is so goes into a memory, and how to act goes into an instruction.
- Keep each person's facts under their name, so one person's preference never becomes
  everyone's rule.
- A procedure you worked out and will need again becomes a skill.
- What this session taught belongs in a doc before a checkpoint folds it away: a summary
  keeps the gist, a doc keeps the fact.
